# D12 产品验收阈值 · 保守建议值方案（v1，供 owner 裁决）

> 依据：docs/board-osptek-p4c5-resource-budget.md 实测数据 + r02-r15
> 真机验证记录。原则：**① 已验证实现值直接冻结（零改动最保守）
> ② 新增值给 ≥2 倍余量 ③ 无测量面的项给"验收方法"不拍数值**。
> 标记：[A]=现有值冻结（批准即生效，无需改码）；[B]=需小实现
> （批准后 I 实装断言/闸）；[C]=defer（产品定义或仪器依赖）。
> 每项可独立批准；批一档做一档。

## 1. 平台基准 [A]

| 项 | 建议值 | 依据 |
|---|---|---|
| 参考板 | Osptek ESP32-P4C5 核心板+底板 V1.3（HP SRAM 768KB/flash 16MB），C5 slave=官方 esp-hosted v3.0.10 自编译（deps/ 体系） | r06/r14/r15 已全冻结 |

## 2. 停止路径 [A+B]

| 项 | 建议值 | 依据/验收方法 |
|---|---|---|
| estop 按下→输出到安全值 | **≤1 ms（硬上限）** | 结构性=ISR 同步直写（无队列/调度，µs 级路径）+r14 万用表定性实证；1ms=百倍余量。[B] 断言=验收批用示波器实测（有仪器前以代码路径审查+WDT 兜底记录） |
| system_fail→输出安全值 | **≤100 ms** | 软路径含 WDT 巡检一拍（1s）——**不符**：实际≤1 巡检周期=1s。保守取 **≤1000 ms**，验收=固件时间戳（fail_reason 留痕时刻 vs 输出写完成——[B] 需在验收批加打印） |
| estop→EVT_ESTOP 观测补发 | **≤2×巡检周期=2 s** | 巡检 1000ms+调度延迟（现有机制，r14 心跳实证） |
| 硬件 WDT 兜底复位 | 巡检停喂→MWDT 复位 **≤10 s** | 实测 8.8s（r02；MIN_TIMEOUT 3s+fallback 2s 配置） |

## 3. 唤醒与电源 [C]

| 项 | 建议 | 依据 |
|---|---|---|
| 唤醒时间 | **defer**——首期不引入睡眠面（板无 deep-sleep 实现；保守=功能不引入，无阈值即无违约风险） | 产品定义后补 |

## 4. 并发 [A]

| 项 | 建议值 | 依据 |
|---|---|---|
| 并发 wasm App 执行 | **1**（单槽串行——现有实现即如此） | 最保守；放宽需新论证 |
| 并发云请求 | **1**（无 pipelining/无后台队列） | r15 实现即如此 |
| 网络连接数 | **1** WiFi 关联 + ≤2 TCP（控制面+观测面） | 现状 |

## 5. 内存 [A+B]

| 项 | 建议值 | 依据/验收方法 |
|---|---|---|
| 链接期静态 SRAM（.dram0.bss+noinit+各栈） | **≤540 KB（70%）** | 实测最大镜像（真云）403KB=52.5%；70% 红线留 30% 余量。[B] 断言=构建脚本读 map 求和，超线 FAIL（一次性脚本，随批入 tools/） |
| 运行时内核堆余量 | **≥64 KB**（k_heap 128KB 的一半） | [B] 验收批加 heap 使用打印（k_malloc 水位快照）；无持续监测前以链接期红线为主闸 |
| mbedtls 会话堆 | 64 KB（现有配置冻结） | r15 实测跑通；收窄实验留优化批（动它不保守） |
| 栈（已定案冻结） | main 32K/tcp_work 8K/esp_hosted event 16K/sysworkq+RX 4K/ISR 2K | r15 攻坚定案值，board 表 §3 |
| PSRAM | 首期**不启用** | A-1 论证不依赖；启用=新批+新红线 |

## 6. 指令与队列 [A+B]

| 项 | 建议值 | 依据/验收方法 |
|---|---|---|
| wasm 单次调用指令配额 | **默认 1×10^8**（100M）；绝对上限 2×10^9（clamp 保持） | 实测正常任务毫秒级完成（百万指令级）；默认值给千倍余量。现状=调用方传 timeout_ms 直映射——[B] 需在装载层加默认配额常量（一次性，~10 行） |
| 事件队列 | 深度 16（现有）；**丢弃率告警阈值：巡检周期内丢弃>0 即观测事件，连续 3 周期丢弃→闸失败** | 满即丢弃计数已实现（events.c）；[B] 补阈值判定进验收闸 |
| 网络依赖防抖 | 恢复=2 连 good（现有）；失败=立即 DOWN（现有） | r06/r15 真机实证，冻结 |

## 7. 模型/云 [A+B]

| 项 | 建议值 | 依据/验收方法 |
|---|---|---|
| 单次调用超时 | **30 s**（现有 chat_once 冻结） | r15 实测往返远小于此；保守上限 |
| 鉴权失败（401/403） | **不自动重试**，报 E_PERM 并 MODEL DOWN（现有） | F-2/r15 额度纪律，冻结 |
| 限流（429） | 不自动重试，E_BUSY；**冷却 ≥60 s 后才允许下一次尝试** | [B] 冷却窗小实现（netmon/assist 层，~15 行）；防失控烧钱 |
| 恢复 | 连续 2 次成功→MODEL UP（同 netmon 防抖，现有） | 冻结 |
| 调用频度上限 | **≤6 次/分钟且 ≤200 次/日**（工厂/调试面另计台账） | [B] 频度守门（assist 层计数，~20 行）；额度纪律 §10.4 变闸 |
| 失败风暴 | 连续失败 ≥3 次→MODEL DOWN 且**不自动恢复重试**（需外部事件/命令恢复） | [B] 风暴计数（netmon 层，~15 行）；保守=失败侧不自动打 |

## 8. 媒体 [C]

| 项 | 建议 | 依据 |
|---|---|---|
| 媒体延迟/格式 | **defer**——首期不启用媒体后端（i2s0 保持 disabled 待上游 PR；D11 一并裁决） | 启用=新批+新阈值 |

## 9. 长期运行与恢复 [A+B]

| 项 | 建议值 | 依据/验收方法 |
|---|---|---|
| WDT 巡检周期 | 1000 ms（现有） | 冻结 |
| 异常复位循环保护 | **1 小时内 ≥3 次异常复位（noinit 留痕计数）→第 4 次启动进安全停机模式（不启动 wasm/云，输出保持安全态，等命令/到场）** | [B] noinit 计数+boot 步骤判定（~30 行，复用 last_reset 机制）；保守=拒绝在异常循环里反复起业务 |
| 异常复位后冷却 | 复位原因为 BOOT/WDT 时，wasm 执行与云调用延迟 **≥60 s**（冷却窗） | [B] 同上批实现；保守缓冲 |
| 泄漏/长期 | 长跑批（≥24h minimal+真云心跳轮询）验收：无 WDT 复位、堆水位漂移 ≤10% | [B] 验收批执行并记录（跑一次即有数据） |

## 10. 汇总：批准即生效路径

- **[A] 项**（本方案主体：平台/停止/并发/内存静态/指令/模型超时与鉴权/巡检）：你逐项打勾即冻结，我把本表移入 rebuild-plan §10.4 附件并关闭对应 blocked。
- **[B] 项**（约 8 个小实现，合计 ~150 行+1 构建断言脚本+2 个验收跑）：一次工程批做完（r16），全绿后 [A]+[B] 合并构成 R13 产品验收的可测断言集。
- **[C] 项**（唤醒/媒体）：随产品定义/上游 PR 再启。

> 数值修订规则：任何阈值放宽需附新实测数据；收紧随时可做。
