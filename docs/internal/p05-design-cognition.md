# P05 设计建议：智脑、经历记忆与长期适应

与[运行时](p05-design-runtime.md)共用任务/能力/时间合同；
状态与待确认项见[总览](p05-design-proposal.md)。
智脑是有状态的机制组合，不是完整脑插件，也不只是 LLM 对话代理。
以下细化均为建议，记忆 features 尚待 owner 确认。

## 1. 模块边界与所有权

| 模块 | 唯一拥有的状态 | 输入/输出与关键端口 | 非职责与故障处置 |
| --- | --- | --- | --- |
| Context | 当前有效观测、派生情境 revision、有界工作快照 | ingest/invalidate/snapshot → 有来源情境 | 不写记忆/人格；过期标未知 |
| Deliberation | 思考轮 ID/代次、触发预算、候选和决策进度 | trigger/step/cancel → no_action/建议/任务提案 | 不执行硬件、不授权限；云故障停用 |
| Model adapter | 请求映射、服务可用性、连接/取消状态 | infer/cancel/structured result | 不写 Context/Memory；未经校验结果只是候选 |
| Affect/drive | 已启用的驱力/短期情感动力状态 | valid inputs/step/reappraisal → state/tags | 不改安全/信任；依产品必要性拒激活或显式失效 |
| Memory | 经历/语义条目、索引、谱系、删除代次与健康 | encode/retrieve/propose/commit/delete → recall/receipt | 不写任务/人格，不读取测试真值 |
| Adaptation | 长期倾向版本、候选和证据窗口 | evidence/review/commit/invalidate → bounded tendencies | 不在线改权重/权限；缺依据不成长 |
| Conversation | 会话/轮次、用户控制、输入输出关联与已播范围 | begin/input/interrupt/end → context/任务请求 | 不拥有全局任务/经历库；清迟到输出 |

工作快照归 Context，跨会话条目归 Memory，不另外建设八个工作空间。
任务/承诺有效状态归运行时 Task；记忆可存带任务引用的经历/提醒线索，
不能从旧记忆复活已取消任务。人格倾向归 Adaptation，不与 Memory 双写。
模块通过窄端口交换快照/候选；装配负责接线，不直接修改内部对象。
现有 affect 单实例用适配层明确限制，不假装已支持多个主体。

## 2. 三种配置与智脑依赖

辅助智能装配 Context、Model adapter 和有限分析策略，不需要情感、
媒体、长期经历或自主行动；建议结果依设备证据，不足明确未知。
模拟智能装配 Context/Deliberation，可选 Affect/Memory/Adaptation；
首产品按已确认要求选择这些能力，媒体是独立可选扩展。
Linux 增强认知是后续配置，不为首期预建完整自我/世界模型模块和空目录。

智脑配置声明云模型为首期必要依赖，失效取消对话、思考和巩固，
不以规则替代智能。固定功能与独立 App 仍归自己的依赖。
记忆配置进一步声明介质/恢复要求；首产品缺卡或不可恢复不激活正常智脑，
只留安全、设置/修复，不创建新角色。
情感禁用不自动禁止合法任务；若产品不能满足连续状态场景，报告产品未达标，
而不是声称框架所有模拟智能必须有情感。

## 3. 情境与模型交互

Context 只保留任务相关的有界快照：能力/任务视图、近期输入、有效状态、
当前交互和可用回忆引用。缺字段不补默认正常值。
来源至少区分设备观测、外部陈述、推断、回忆、想象和自身动作；
模型描述不升级为观测，影子输出不证明物理完成。

模型请求 envelope 推荐：

```text
request/round/session IDs + instance/cancel generation
context revision + evidence refs + role constraints
allowed capability schemas + data-egress authorization
model/service requirement + deadline + token/iteration/output budgets
```

模型只返回有限类型候选：解释/建议、no_action、能力调用提案、
记忆巩固或重评价提案；不返回任意宿主代码执行。
语法、长度、来源、能力版本、期限及策略全部设备侧检查。
LLM 置信度仅候选属性，不成为事实可靠度或执行授权。
外发使用最少必要片段，不每轮上传全部记忆/日志/媒体。
ASR/TTS/视觉可各有服务适配和依赖，统一请求关联但不强制同一家模型。
多模型切换只对明确兼容 schema 和数据授权的配置允许，失败不暗换服务。
Model adapter 不持有绕过授权的原始外发入口：每次发送前经运行时数据
外发门复查目标、类别、授权/删除代次和会话有效性。总览图的智脑到模型
连线表示服务关系，不表示直接越过受控传输。

## 4. 触发、决策、执行三段

```text
idle → scheduled → gathering → waiting_model → validating → settled
任意在途 → cancelling → cancelled
模型/配置依赖失效 → stopped；故障 → failed
```

触发来自新事件、任务/内部状态变化、有界周期，不由每个信号变化无限调用。
触发预算与对外行为许可分开：勿扰可以阻止输出，是否省略内部思考由策略决定。
现有 ignition 因子/门算法可复用，但其“quiet 也挡思考”等产品规则需适配，
不能把旧实现当成新共识自动冻结。

Gathering 读取 revision 快照并做有界检索；等待云期间不占状态写锁。
Validating 校验结果结构/来源；状态变化可有界重新读取/重新思考，
到预算/期限则结束，不能一直追逐最新情境。
Settled 可为 no_action、辅助建议或模拟任务候选；候选交运行时门控，
执行前重新检查用户控制/能力/依赖/资源，不直接发硬件写。
结果与实际行为反馈更新相关模块，不把生成文字记为已经说出或行动完成。

## 5. 对话与表达

首产品体验通过 Conversation 装配媒体、模型、任务与表达策略；
不是通用智脑必须含麦克风。无媒体配置可用测试输入驱动同一合同。
每轮绑定采集/识别/推理/TTS/播放 IDs 和输出 generation；
开始新轮/停止时撤旧代次，迟到片段不能重新开口。
本地停止先使播放/请求失效，再清待播/取消模型，不能等待网络返回。
已听范围来自后端播放进度及其精度合同；不能用“已提交 TTS”标记用户已听。
播放进度不够精确时注明边界，重建上下文不宣称未播内容已传达。

输入默认不持久保存原始媒体；对话成为经历也需选择性与授权。
用户说“过去发生 X”：可以记录“用户陈述 X”的交互，
不能把 X 编码为设备亲自经历。图像文字/网页/模型返回均不改变系统指令优先级。

## 6. 记忆内部设计建议

### 子职责而非八个强制服务

| 子职责 | 内容与 owner | 首期推荐 |
| --- | --- | --- |
| Encoding | Memory 审核来源/选择条件，形成经历切片 | 必需，选择性编码，不默认全对话 |
| Episodic store | Memory 保存互动/自身动作/结果及来源引用 | 必需，跨重启连续 |
| Semantic derivation | 从经历生成可追溯概括/关系，不造亲历 | 最小版本，候选提交 |
| Retrieval | 有界索引/线索检索，返回 recall 来源与未知 | 必需，不把搜索无命中当正常记得 |
| Consolidation/forgetting | 有界批处理，谱系与版本变更 | 必需机制；细参数待确认 |
| Health/control | 恢复、容量、删除/纠正/不记住、写入回执 | 管理最低集建议，产品入口待确认 |

工作上下文不等于持久 working 数据库；情感价值标注是条目属性，
前瞻性状态引用任务；元记忆先用来源/可靠度/健康与未知表示。
程序性技能、自传性组织、完整八子系统不作为首期强制独立模块。
参考原 Galatea `design/lld/L06_memory.md` 的机制含义，
不复刻 Python 数据库、研究门编号或保护集凌驾用户删除。
该研究文件在仓库外，贡献者可从[研究边界](../galatea.md)了解来源；
本设计不依赖外部研究文件才能构建。

### 条目与持久结构

```text
Memory record:
  id/version, kind, source_kind, event/action/result refs
  time domain/range, valid scope, content/ref
  reliability/unknowns, bounded affect tag, strength/access metadata
  parents/derivation receipt, retention/consolidation state
  deletion generation, schema/checksum
```

检索返回 `RECALLED` 加原始来源，不重新标 PERCEIVED。
强情绪可调选择/检索权重，不提高事实可靠度。语义矛盾记录情境/来源，
不强制抹成一个永久标签。内容和 parents/ref 数量有上限，截断显式标记。

MCU 推荐评估 TF 有界段日志 + 稀疏索引 + 可恢复版本清单，
RAM 保存当前上下文与有限缓存；Flash 存小恢复元信息/配置而非全部经历。
Linux 可评估 SQLite 等独立后端，但跨平台共享提交/删除/检索语义，
不承诺相同文件格式或逐字节库 digest。
备选 MCU 数据库需测 RAM/写放大/检索/中断成本后选择，不凭 TF 大就装全库。

推荐提交过程：写新段/索引 → 校验及后端同步 → 发布新版本清单 →
持久回执 → 延后清旧版本。启动验证清单/段一致性，损坏隔离并修复，
不自动格式化。同步/rename/TF 控制器的保证必须后端声明与实测，
应用日志无法修复任意 FAT 元数据/介质损坏。
未证明耐掉电前不能宣传提交物理持久；普通诊断文件读写通过不等于此合同通过。
记录 `queued/committed/failed/unknown`，不让排队回执冒充记忆已保存。

### 巩固、遗忘与删除

巩固：触发条件/空闲与预算 → 选片段 → 获外发许可 → LLM 候选 →
Memory 校验来源/父代次/结构 → 原子版本提交 → 回执。
用户活动优先，模型/存储依赖失效取消；结果父版本被删或修改则拒绝。
用批次游标/局部索引，禁每次 tick 全库扫描/落盘。
遗忘按时间/强度/关联等有界策略，先改变检索可见性/抽象再按预算回收；
不能无痕改写经历历史或把自然遗忘当用户已删除。

删除建议先持久提交删除标记/代次，再屏蔽索引、缓存、派生概括、
已构建上下文及在途巩固/适应候选，后做物理回收。
删除未持久成功明确失败/待完成；不能向用户报“已删”后重启复活。
跨 Memory/Adaptation 清理不假原子事务：读取/提交端检查共同删除代次，
副本清理逐步收敛，有失败状态并阻止旧派生内容消费。
普通文件删除不保证物理不可恢复，已外发数据不保证云端撤回；
支持什么删除/服务保留范围必须明确说明。

“不要记住”推荐绑定本轮/内容选择，在编码前阻止，并移除未提交候选；
不是仅在 LLM 提示里加一句话。用户纠正是新版本/来源与失效关系，
不是把用户新说法当设备历史观测。备份/跨设备迁移建议延期，
未来恢复必须尊重删除代次，不能无条件导回旧经历。

只读/空间满/写失败不同于缺卡或不可恢复：
先健康事实与拒写合同，产品是否暂停/限时修复另确认；
不能自行进入无记忆模式或保留无限未落盘队列。

## 7. 情感与长期适应

现有 drive/emotion/ignition 纯算法先保持来源与数值回归，
由适配层解释有效输入、时间与配置。当前拍数 τ 不自动成为跨平台
现实时间；固定步长调度或 dt 转换须单独对照，睡眠/缺源不能假 tick。
只接受受控重评价候选并检查来源/范围/回执，不允许 LLM 直写九维数值。
产品特有 social/伦理表达策略与框架不可改权限分开，不把算法闩锁当安全认证。

Adaptation 推荐慢时间尺度、有限倾向空间和可解释证据窗口：
重复经历 → 稳定证据摘要 → 候选更新 → 约束检查 → 版本提交。
更新有幅度/频率上限、矛盾情境与置信，单事件不改人格；
允许数个月或更久，不以运行时长本身触发成长。
可调的是表达/偏好/情境评价，不是身份、权限、信任或核心角色约束。
用户控制和初始角色约束优先，具体可适应维度和用户查看/纠正入口待定。
删除证据需使相关倾向可重评/失效，不能保留永久无依据人格标签。

## 8. 验证：因果机制与工程可靠性分开

- 观测/陈述/回忆/想象混合，断言来源不升级；检索未知和旧观测不能伪现在。
- 冻结/重置/伪更新对照，证明跨重启经历实际影响选择；
  不用日志“写成功”代替行为差异。
- 情感、经历、适应分别消融，说明差异及误差；合法任务与保护行为不被移除。
- 巩固删除竞态、空间满/只读/坏段/每个提交点中断，验证不复活已删内容。
- 模型超时/迟到/恶意结构结果，断言不越权、不无限循环、不直写状态。
- 真正数个月性格观察另报，测试虚拟时间只证明动力机制与边界。
