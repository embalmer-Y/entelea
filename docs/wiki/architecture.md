# 整体架构与平台

Entelea 是按需裁剪的模块化单体，不是把每项功能拆成独立服务。
设备角色、算力和行动权限分别决定：较强的硬件不自动获得更大权限。

```text
产品/诊断装配                         独立 Forge 工厂
        |                              | 受控产物/证据
        v                              v
辅助智能、媒体、记忆、网络         签名包 -> 试用状态
        |                              |
        +--> principal / 任务 / 资源 <-+
                       |
                 输出安全保护
                       |
              Zephyr / Linux 端口
```

图是职责关系，不意味着图中的全部路径都已组成可验收产品。具体完成度见
[RF1 复核](../rf1-validation.md)。

## 分层

- [公共合同与原语](../../framework/common/contract.md)：错误、来源、
  时钟、截止时间、CBOR 和 SHA；不依赖完整操作系统。
- [监督](../../framework/runtime/supervision/contract.md)与
  [执行](runtime.md)：启动、故障、输出保护、授权、任务和资源。
- [服务](services.md)：存储、模型、网络及可选媒体/记忆/情感；能力按
  装配和实际依赖启用，不把采集自动当成保存或上传。
- [包与交付](delivery.md)：验证包事实、受限执行、候选试用和工厂职责
  分开。生成代码不能自授权限或绕过设备保护是设计目标；试用确认的权限
  已与运行时 natives 授权取交集；稳定集准入（试用结束后的长期启用）已按
  D-E 实施，但断电窗口未经真机验证，不应把该目标当成已证明的保证。
- [平台](../../platform)：实现时钟、存储、驱动和选定传输，并把机制
  装配为具体镜像；公共接口不应依赖某个平台的私有 OS 类型。

## Zephyr 与 Linux

Zephyr 面向受限 MCU：当前包含启动、静态有界表、输出安全、
flash 端口和单实例 WAMR 等具体实现。最小镜像与 WiFi、云、工厂等
诊断镜像的装配并不完全相同，不能由某个诊断的结果推断所有镜像一致。

Linux 使用部分同源机制和 POSIX 垫片；按已批准的 R-V5 当前主要是
合同测试和诊断，不是完整 Linux Wasm/App 宿主，也没有以当前源码
在 ARM64 上完成运行验收。两端共享语义不意味着整个 Zephyr 服务被移植。

## 关键数据流

- **辅助智能的保护输出**：候选经目标能力和 principal 判权、适用的
  资源预算后进入 safety commit，再执行限幅、状态检查及驱动写入。
  `safety_commit` 自身不检查 principal；不能把此调用链推广为所有
  调用方都已机械强制判权。后端报告成功也不等于已测得真实物理输出。
- **模型建议**：依赖状态与预算允许 → 模型适配器请求 → 上层组装
  结构化候选 → 执行门；`accepted`、`confirmed` 和 `unknown` 不等价。
- **候选交付**：工厂产包 → 设备暂存与验签 → 试用确认 → 受限执行。
  当前设备侧已把确认的权限列表与宿主授权取交集，并已按 D-E 实施稳定集准入，
  不能把此图当作完整安全闭环。
