# 包、试用与工厂

## 包事实与受限运行

[包合同](../../framework/services/package/contract.md)中，TSAP v2 经
暂存、摘要和 COSE/Ed25519 验签后提供包事实；`activate` 记录槽位，
本身不授予运行资格。WAMR 当前为单实例，宿主注入 principal，
调用前还要经过试用门。默认 `1e8` 指令配额需要调用默认入口；
它不是墙钟硬截止。Lua 已有接入合同和 C 预算机制桩，但真实 Lua VM
的资源与中断可行性尚未验证，也没有正式 Lua VM。

## 候选试用

[交付合同](../../framework/services/delivery/contract.md)记录单候选的
PENDING、ACTIVE、REJECTED 和 TIMEOUT，并比较展示的包摘要、权限位图、
版本、槽和纪元。候选槽在确认前或字节改变后不得运行；跨重启恢复
要求两份状态可读、一致，否则进入 UNKNOWN 且两槽受限。状态落盘仍由
装配层显式触发，旧/损坏记录的维护恢复策略尚未制定。
确认纪元耗尽后拒绝新候选，避免回绕后旧确认复活；维护方案仍待制定。
`confirm` 只校验调用方提供的对象，不验证用户身份或真实交互；可信
调用方必须先取得用户授权。ACTIVE 表示试用，不等于晋升稳定集。

**关键缺口**：确认位图没有与实际 WAMR principal 权限表绑定，
工厂候选的预算也尚未与签名 manifest 和实际预算证明一致。
可选失败探针和证据见 [RF1 复核](../rf1-validation.md)。
非候选槽、试用结束后的稳定集准入以及并发改槽的摘要/装载窗口也未
形成完整产品保障，因此不能把确认状态机等同于全包授权闭环。

## Forge 与设备的边界

OpenHands Software Agent SDK 负责独立工厂的通用编程循环；Forge 负责
领域工具、受控验证、产物组装及受控签名/交付。工厂自述和结构化结果
不是独立验证；开发夹具的自动确认不是用户验收。

本机现有 Forge 工作区独立于此 Git worktree，尚缺稳定的独立版本锚点
和可证明的产品隔离。历史模型/硬件实验不自动授权后续云调用、烧录、
外发或部署。设备保留最后的权限、安全和试用裁决职责。
