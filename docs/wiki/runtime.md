# 监督与执行

本页描述线程/ISR、权限和安全边界；具体接口和错误码以各公共头及合同
为准，不能把下面的概述当作额外 API。

## 事件、启动与监督

[监督合同](../../framework/runtime/supervision/contract.md)中的事件总线
对线程同步分发，对 ISR 使用有界队列；ISR 异步载荷必须有足够长的
生命周期。队列满会计数，不能把事件通知当作当前权威状态。

[启动表](../../platform/zephyr/boot_steps.c)当前依次执行 estop、
输出上电安全态、WDT、监督、存储和启动保护；不同镜像还要落实自己的
装配要求。WDT 时钟持续不可知会进入故障，`system_fail` 使新的巡检
不再喂狗；已在飞的喂狗调用可能完成。当前源码的物理复位时间仍需要
独立测量。

## 输出保护与驱动

[安全合同](../../framework/execution/safety/contract.md)区分上电、
断链、故障和 ACTIVE。提交时检查状态、限幅、速率、预算及后端结果；
强停失败不能伪称安全值已经落到硬件。安全影子只记录软件确认的结果。
[drivers.c](../../framework/execution/safety/drivers.c) 是源码分类中
唯一允许直接调用 Zephyr 输出驱动的保护落点；机械检查不是完整链接级
防绕过证明。未绑定通道可作为纯软件通道，不能当作真实设备已工作。

## principal 与能力

[principal/能力合同](../../framework/execution/capability/contract.md)
由可信宿主绑定具体权限表；模型输入和 App 整数不构成身份。能力描述符
把可操作目标映射到实际安全通道，判权应使用真实类和实例，而不是
仅比较上层的名字。

不可伪造令牌。Wasm native 接口须由宿主注入主体，不可让 App 自选。

## 资源与任务

电源请求在同一保护锁序内完成预算检查和安全提交，计账使用安全
readback；它不是独立的物理电流测量。任务机区分 ACCEPTED、RUNNING
和终态：取消不会撤回已发生的效果，`UNKNOWN` 的非幂等动作不可自动
重试。带截止时间的任务在时钟不可知时拒绝受理或开始；已运行任务的
效果仍由上层如实处理。接口与并发前提见
[能力/资源/任务合同](../../framework/execution/capability/contract.md)。
