# 板级工具

此目录包含串口、TLS、网络接收、部署及验收辅助工具；板级应用工程位于
`firmware/tests/board/`。它们不是普通 CI 或主机测试的一部分，也没有因本次
迁移而重新通过所有真机验证。

## 使用边界

- **设备复位、烧录、配置、信任更新、App 安装、网络部署和真实模型调用均须
  事先获得明确授权。** 先确认目标设备、串口、网络、分区、固件和恢复方案。
- `e2e_*.py`、`demo_multiapp.py` 等可能写入设备；`demo_llm_creation.py`、
  `demo_pdm.py`、`demo_threads.py` 和 `nvd_acceptance.py` 可能调用真实模型。
  部分脚本保留特定实验环境的节点、地址、串口和输出路径，必须先审查源码和
  适配目标，不能直接复制旧环境命令。
- 仓库中的测试根密钥和示例包是公开测试材料，不能用于生产配置。证书和 Wi-Fi、
  模型凭据应留在仓库外或环境变量中。
- `gen_tls_certs.sh` 会覆盖输出目录中的 router 和 device 密钥、证书；使用前
  必须确认输出位置及现有文件，不能对生产凭据目录执行。
- 先确保串口只有一个持有者；检查目标板的引脚、分区和硬件安全态。主机测试
  不能证明物理动作或故障处理安全。

`console_*`、`dav_recv.py`、`pdm_recv.py` 和 `p4_udp_echo.py` 为观测或接收
辅助；`gen_*`、`ota_client.py` 和其余脚本可能写文件或更改设备状态，应先
检查实现。板级 blob 使用相应 Zephyr 版本的官方准备流程。

固件开发入口见[开发指南](../../docs/development.md)，当前验证分类见
[测试指南](../../docs/testing.md)。历史证据应回溯[迁移出处](../../docs/provenance.md)
所列原项目提交，不应当作当前设备的验收证明。
